Merge Sort

What is Merge Sort?

Merge sort is a divide-and-conquer sorting algorithm that works by breaking an array into smaller pieces, sorting those pieces, and then combining them back together in sorted order. It's one of the most efficient sorting algorithms because it has predictable performance regardless of the input data.

The key insight behind merge sort is that it's much easier to merge two already-sorted arrays into one sorted array than it is to sort an unsorted array from scratch. So the algorithm takes advantage of this by recursively dividing the problem into smaller sorted sub-problems.

How Merge Sort Works

Merge sort operates in two main phases:

Phase 1: The Divide Step

The algorithm recursively splits the array in half until each piece contains only one element. A single element is considered "sorted" by definition, so this process continues until we can't divide anymore. Think of it like repeatedly cutting a deck of cards in half until you have individual cards.

Phase 2: The Merge Step

Once we have all the individual elements, we start combining them back together. We compare elements from two sorted groups and place the smaller one into the result array first. We keep doing this, moving through both groups, until all elements are merged back into a single sorted array.

The Merge Operation (The Heart of the Algorithm)

The merge operation is where the magic happens. We have two sorted arrays, and we need to combine them into one sorted array. Here's the strategy:

  1. Create an empty result array that will hold all elements
  2. Keep track of a pointer at the start of each of the two input arrays
  3. Compare the elements at both pointers
  4. Move the smaller element to the result array and advance that pointer
  5. Repeat until one array is completely copied
  6. Copy any remaining elements from the non-empty array

Time and Space Complexity

Time Complexity

Best, Average, and Worst Case: O(n log n)

Why O(n log n)? The array gets divided into halves repeatedly, which takes log(n) levels of division. At each level, we have to merge all n elements. So that's n × log(n) operations total. This is consistent regardless of whether the array is already sorted, reverse sorted, or random—merge sort doesn't care about the input order.

Space Complexity

O(n)

Merge sort requires extra memory for the temporary arrays used during the merge operations. In the worst case, we need space equal to the size of the original array. This is why merge sort is not "in-place"—it trades memory for guaranteed efficiency.

Why Is O(n log n) Good?

Compared to simpler algorithms like bubble sort (O(n²)), merge sort is dramatically faster for large datasets. For 1 million elements:

  • Bubble sort: ~1 trillion operations
  • Merge sort: ~20 million operations

Code Implementation

JavaScript Implementation


function mergeSort(arr) {
  // Base case: arrays with 0 or 1 element are already sorted
  if (arr.length <= 1) {
    return arr;
  }
  
  // Find the middle point
  const mid = Math.floor(arr.length / 2);
  
  // Divide: split the array into two halves
  const left = arr.slice(0, mid);
  const right = arr.slice(mid);
  
  // Conquer: recursively sort both halves
  const sortedLeft = mergeSort(left);
  const sortedRight = mergeSort(right);
  
  // Combine: merge the sorted halves
  return merge(sortedLeft, sortedRight);
}

function merge(left, right) {
  const result = [];
  let leftIndex = 0;
  let rightIndex = 0;
  
  // Compare elements from left and right arrays
  while (leftIndex < left.length && rightIndex < right.length) {
    if (left[leftIndex] <= right[rightIndex]) {
      result.push(left[leftIndex]);
      leftIndex++;
    } else {
      result.push(right[rightIndex]);
      rightIndex++;
    }
  }
  
  // Add remaining elements from left array
  while (leftIndex < left.length) {
    result.push(left[leftIndex]);
    leftIndex++;
  }
  
  // Add remaining elements from right array
  while (rightIndex < right.length) {
    result.push(right[rightIndex]);
    rightIndex++;
  }
  
  return result;
}

// Example usage
const arr = [38, 27, 43, 3, 9, 82, 10];
console.log(mergeSort(arr)); // [3, 9, 10, 27, 38, 43, 82]

Advantages and Disadvantages

Advantages

  • Guaranteed O(n log n): No matter the input, merge sort always performs consistently
  • Stable: Equal elements maintain their relative order from the original array
  • Predictable: You always know how long it will take
  • Works well with linked lists: Unlike quicksort, merge sort doesn't require random access
  • Parallelizable: The divide step can easily be split across multiple processors

Disadvantages

  • Extra memory required: O(n) space for temporary arrays makes it memory-intensive
  • Not in-place: Can't sort within the original array without significant overhead
  • Slower on small arrays: The overhead of recursion and merging isn't worth it for tiny datasets
  • Slower in practice than quicksort: Although quicksort has worse worst-case complexity, it's often faster in real-world scenarios due to cache efficiency

When to Use Merge Sort

  • You need guaranteed performance: When O(n log n) worst-case is critical
  • Stability matters: When you need to preserve the order of equal elements
  • Working with linked lists: Merge sort doesn't require random access like quicksort does
  • External sorting: Sorting data from disk or other slow storage where you can't fit everything in RAM
  • Parallel processing: When you want to leverage multiple CPU cores

Key Takeaways

  1. Merge sort uses divide-and-conquer: split the problem smaller, solve the small problems, combine the solutions
  2. It's efficient because merging two sorted arrays is linear time
  3. O(n log n) time complexity makes it much faster than simple sorts for large arrays
  4. The tradeoff is extra memory usage for the temporary arrays
  5. It's a stable sort and works consistently regardless of input data
