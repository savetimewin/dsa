Time and Space Complexity

Interview-ready explanation for the hash set solution.
Time complexity: O(n)
Reason: 
for num in nums:
This loop can visit each element in nums once.
Inside the loop: 
if num in seen:
Checking membership in a set is O(1) on average. 
seen.add(num)
Adding to a set is also O(1) on average.
So the total is: 
n elements × O(1) work per element = O(n)
Best case: O(1)
Example: 
nums = [1, 1, 2, 3]
It finds the duplicate immediately and returns True.
Worst case: O(n)
Example: 
nums = [1, 2, 3, 4]
It must check every number before returning False.
Space complexity: O(n)
Reason: in the worst case, every number is unique, so seen stores all n numbers.
Other solution tradeoffs:
Brute force
Compares every pair.
Time:  O(n²)
Space: O(1)
Space is O(1) because it only uses loop variables like i and j; it does not create a hash set, hash map, or extra array that grows with input size.
Hash set
Improves time by remembering numbers already seen.
Time:  O(n)
Space: O(n)
This is the main solution to know. It trades extra memory for faster lookup.
Sorting
If asked to reduce extra space and mutation is allowed, sort first, then check adjacent values.
Time:  O(n log n)
Space: O(1) or O(n)
Sorting usually uses less extra space than a hash set, but the exact space depends on the sorting algorithm / implementation.
Interview summary: 
Brute force compares every pair: O(n²) time, O(1) space.

Hash set improves time: O(n) time, O(n) space.

If we are asked to reduce extra space and mutation is allowed, sorting is possible:
O(n log n) time, usually less extra space than a hash set; O(1) or O(n) space depending on the sorting algorithm.
