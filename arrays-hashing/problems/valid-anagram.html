Solution 1: Sorting Approach

Sort both strings. If the sorted character lists match, the strings contain the same letters with the same counts.
Intuition
If two strings are anagrams, they must contain exactly the same characters with the same frequencies. Sorting both strings arranges the characters in a consistent order. If the sorted versions are identical, then every character and its count match.
Algorithm
  1. If the lengths of the two strings differ, return False immediately because they cannot be anagrams.
  2. Sort both strings.
  3. Compare the sorted versions. If they are equal, return True; otherwise, return False.

Time and Space Complexity: Sorting Solution

Interview-ready explanation for sorted(s) == sorted(t).
Time complexity: O(n log n + m log m)
Reason: 
if len(s) != len(t):
    return False
return sorted(s) == sorted(t)
The length check is O(1). If the lengths match, sorted(s) sorts the characters of s, and sorted(t) sorts the characters of t.
Sorting cost: 
sorted(s) = O(n log n)
sorted(t) = O(m log m)
After sorting, Python compares the two sorted lists. That comparison is O(min(n, m)) in many mismatch cases and O(n) when both strings have the same length and all characters must be checked.
So the total is: 
O(n log n) + O(m log m) + O(min(n, m)) = O(n log n + m log m)
Here, n is the length of s, and m is the length of t. If both strings have the same length, this simplifies to O(n log n).
Important detail
This version checks length first. 
if len(s) != len(t):
    return False
This avoids sorting when the strings cannot possibly be anagrams.
If lengths differ
Example: 
s = "ab"
t = "a"
It returns False immediately before sorting.
Space complexity: O(n + m)
Reason: sorted(s) and sorted(t) create new sorted lists of characters.
Final answer:
Time:  O(n log n + m log m)
Space: O(n + m)

Solution 2: Hash Map Approach

Count character frequencies with two dictionaries, then compare the dictionaries.
Intuition
If two strings are anagrams, they must use the same characters with the same frequencies. Instead of sorting, count how many times each character appears in both strings. By using two hash maps, one for s and one for t, we track the frequency of every character. If both frequency maps match exactly, the strings are anagrams.
Algorithm
  1. Create two hash maps: a for s, and b for t.
  2. Loop through s and increase the count for each character in a.
  3. Loop through t and increase the count for each character in b.
  4. Compare the two maps. If they are equal, return True; otherwise, return False.

Time and Space Complexity: Hash Map Solution

Interview-ready explanation for the two-loop dictionary-counting solution.
Time complexity: O(n + m)
Building the first frequency map: 
for char in s:
    a[char] = a.get(char, 0) + 1
This loop scans s once, so it costs O(n). Each dictionary lookup/update is O(1) on average.
Building the second frequency map: 
for char in t:
    b[char] = b.get(char, 0) + 1
This loop scans t once, so it costs O(m).
Comparing the maps: 
return a == b
Dictionary comparison checks whether the stored character frequencies match. Under the lowercase-English-letter constraint, there are at most 26 keys, so this comparison is O(1).
So the total is: 
O(n) to scan s + O(m) to scan t + O(1) to compare maps = O(n + m)
Where n is the length of string s and m is the length of string t.
Space complexity: O(1)
Reason: for the standard Valid Anagram constraints, the strings contain lowercase English letters, so the dictionaries hold at most 26 different characters. Since 26 is constant, auxiliary space is O(1).

If the input allowed arbitrary characters with an unbounded alphabet, this would be O(n + m) space.
Final answer:
Time:  O(n + m)
Space: O(1)
