Solution 1: Sorting Key Approach

Sort each string to create a stable key, then group original strings that share the same key.
Intuition
Anagrams become identical when their characters are sorted. For example, "eat", "tea", and "ate" all become "aet" after sorting. By using the sorted version of each string as a key, we can group all anagrams together. Strings that share the same sorted form must be anagrams, so placing them in the same group is both natural and efficient.
Algorithm
  1. Create a hash map where each key is the sorted version of a string, and the value is a list of strings belonging to that anagram group.
  2. Iterate through each string in the input list:
    • Sort the characters of the string to form a key.
    • If the key does not exist yet, create an empty list for that key.
    • Append the original string to the list corresponding to this key.
  3. After processing all strings, return all values from the hash map, which represent the grouped anagrams.

Time and Space Complexity: Sorting Key Approach

Interview-ready explanation for key = ''.join(sorted(string)).
Time complexity: O(m * n log n)
Reason: 
for string in strs:
    key = ''.join(sorted(string))
    h[key].append(string)
There are m strings. For each string, sorting up to n characters costs O(n log n). Creating the key with ''.join(...) costs O(n), but sorting dominates that cost.
So the total is: 
m strings * O(n log n) per sorted key = O(m * n log n)
Here, m is the number of strings and n is the length of the longest string.
Important detail
The hash map operations are average-case O(1) per string. 
if key not in h:
    h[key] = []
h[key].append(string)
The main cost is not the dictionary insertion. The main cost is sorting each string.
Example
strs = ["eat", "tea", "tan", "ate"]
Each word is sorted once. Words with the same sorted form are grouped under the same key.
Space complexity: O(m * n)
Reason: the hash map stores grouped output containing all strings. In the worst case, the total stored characters across all groups is proportional to m * n. The sorted keys also require extra space, but the dominant stored output is still proportional to all input strings.
Final answer:
Time:  O(m * n log n)
Space: O(m * n)

Solution 2: Character Count Tuple Approach

Use a fixed 26-slot frequency array as the anagram key instead of sorting each string.
Intuition
Instead of sorting each string, we can represent every string by the frequency of its characters. Since the problem uses lowercase English letters, a fixed-size array of length 26 can capture how many times each character appears. Two strings are anagrams if and only if their frequency arrays are identical. By converting the frequency array to a tuple, we can safely use it as a dictionary key and group all strings that share the same character counts.
Algorithm
  1. Create a hash map where each key is a 26-length tuple representing character frequencies, and each value is a list of strings belonging to that anagram group.
  2. For each string in the input:
    • Initialize a count array of size 26 with all zeros.
    • For each character char in the string, compute ord(char) - ord('a') to find its alphabet index.
    • Increment the value at that index.
    • Convert the count array to a tuple and use it as the key.
    • Append the original string to the list associated with this key.
  3. After processing all strings, return all the lists stored in the hash map.

Time and Space Complexity: Character Count Tuple Approach

Interview-ready explanation for count[ord(char) - ord('a')] += 1 and res[tuple(count)].append(string).
Time complexity: O(m * n)
Reason: 
for string in strs:
    count = [0] * 26
    for char in string:
        count[ord(char) - ord('a')] += 1
    res[tuple(count)].append(string)
There are m strings. For each string, we scan up to n characters. Each character updates one bucket in the fixed 26-slot array. Creating count = [0] * 26 and converting tuple(count) both cost O(26), which is constant because 26 does not grow with the input.
So the total is: 
m strings * O(n) character scan = O(m * n)
Here, m is the number of strings and n is the length of the longest string.
Why this is faster than sorting
Sorting each string costs O(n log n). Counting each string costs O(n) because each character is touched once.
Important detail
The tuple key always has length 26, so comparing and hashing the key is treated as constant time for this lowercase-English-letter version of the problem.
Space complexity:
  • O(m) extra space for the hash map keys/groups structure.
  • O(m * n) space for the output list, because all original strings appear in the returned groups.
The temporary count array is O(26), which simplifies to O(1) per processed string.
Final answer:
Time:  O(m * n)
Space: O(m) extra space + O(m * n) output space
